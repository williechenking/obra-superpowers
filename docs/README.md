# 爬樓梯訓練(網頁版)

不需要 Mac、Xcode 或 App Store。用 iPhone 的 Safari 開一個網址,加入主畫面後就像一般 App 一樣使用。兩人各自記錄自己的進度,App 會透過 Firebase 自動同步,雙方都能即時看到對方練到哪裡。

## 這個 App 做什麼

跟原本規劃的一樣:
- **爬樓梯**:記錄今天完成第幾趟(每趟 = 爬 13 層樓梯 + 搭電梯下樓)。目標趟數每過一個日曆天自動 +1。
- **Cindy**:記錄今天完成第幾組,目標組數預設沿用前一天。
- 按「完成一次」立刻上傳到共用的 Firebase 資料庫。
- 「對方的進度」區塊每 15 秒自動更新一次,回到 App 前景時也會馬上刷新一次。
- ⚙️ 設定:選擇自己是「老公」還是「老婆」,填入雙方共用的 Firebase 位址。
- ✏️ 編輯:手動校正今天的天數/趟數/組數。

## 第一步:讓這個網頁能被手機打開(GitHub Pages,免費)

這個資料夾(`docs/`)已經是完整的靜態網頁,你只需要在 GitHub 上開啟 Pages 功能:

1. 到這個 repo 的 **Settings → Pages**。
2. Source 選「Deploy from a branch」。
3. Branch 選 `claude/stair-training-progress-app-5twj75`(目前這個分支),資料夾選 `/docs`,按 Save。
4. 等 1 分鐘左右,頁面會顯示網址,通常長得像:
   `https://williechenking.github.io/obra-superpowers/`
   這就是你老婆之後也要打開的網址。

> 之後如果把這個分支合併回 `main`,記得回到 Settings → Pages 把 Branch 改成 `main`,網址不會變。

## 第二步:建立共用的 Firebase 資料庫(只要做一次,由你們其中一人操作)

1. 瀏覽器打開 https://console.firebase.google.com ,用 Google 帳號登入,建立一個新專案(免費方案即可,不需要信用卡)。
2. 進到專案後,左側選單「Build」→「Realtime Database」→「建立資料庫」。地區隨意選,規則先選「測試模式」也可以,之後換成下面這組規則。
3. 進到「規則(Rules)」分頁,貼上:

   ```json
   {
     "rules": {
       "couples": {
         "$room": {
           ".read": true,
           ".write": true
         }
       }
     }
   }
   ```

   這代表只要知道完整的資料庫網址「加上」房間代碼這兩樣東西的人就能讀寫資料。因為只有訓練組數、趟數這種低敏感度資料,用一組長一點、不會被猜到的房間代碼(例如 `willie-jane-2026-9f3a`)當密碼即可。**不要把房間代碼公開分享出去。**
4. 在 Realtime Database 頁面上方會看到資料庫網址,長得像:
   `https://你的專案id-default-rtdb.firebaseio.com`
   記下這個網址。

## 第三步:兩支手機分別設定並加入主畫面

**你的手機:**
1. Safari 打開第一步拿到的網址。
2. 按下方分享圖示(方框加箭頭)→「加入主畫面」→確定。桌面就會出現一個 App 圖示,之後直接點它開,不會有 Safari 網址列。
3. 打開這個「App」,按右上角 ⚙️ 進入設定。
4. 「我是誰」選「老公」。
5. 貼上 Firebase Database URL,以及你們一起決定的「房間代碼」。
6. 按「測試連線並上傳一次我的進度」,看到「✅ 已成功上傳」代表設定成功。按「完成」。
7. 按左上角 ✏️,把今天實際的天數/已完成趟數/組數填正確,按「儲存」。

**老婆的手機:**
重複上面同樣的步驟,只差在第 4 步選「老婆」,第 5 步要填「完全一樣」的 Database URL 和房間代碼。

設定完成後,兩邊按「完成一次」時,對方打開 App(或最多等 15 秒)就會看到最新進度。

## 資料存在哪裡

- 每天的進度存在自己手機瀏覽器的 `localStorage`,離線也能記錄按鈕點擊。
- 一有變動就會嘗試上傳到你們設定的 Firebase Realtime Database;上傳失敗(例如沒網路)畫面上會顯示錯誤訊息,之後有網路時再按一次或回到前景會自動重試。
- Firebase 位址、房間代碼、身分選擇都只存在自己手機的瀏覽器裡,不會被上傳。

## 之前做的 iOS 原生版(`StairTraining.swiftpm`)怎麼辦?

先保留在 repo 裡沒有刪除。如果你之後有機會拿到 Mac,可以直接用 Xcode 打開那個資料夾,功能是同一套邏輯(只是原生版當時走的是「LINE 通知」設計,如果要接續用,需要把它也改成 Firebase 版本;目前主力維護的是這個網頁版)。日常使用建議就先用這個網頁版即可。
